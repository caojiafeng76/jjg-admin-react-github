# 性能与代码规范优化清单

> 本文档是项目优化任务的唯一跟踪清单。**使用规则：完成一项，就在该项的 `[ ]` 里打勾 `[x]`，并在 CHANGELOG.MD 追加对应记录。** 修复问题的工作流：带着本文档 → 逐项修复 → 完成一项勾一项 → 验证 → 更新 CHANGELOG.MD。

## 使用规则（必读）

1. 修复问题时，打开本文档作为跟踪清单，**只修复清单内或用户明确指定的项**，不顺手重构无关代码。
2. **完成一项打一个勾**（`[ ]` → `[x]`），与本次改动在同一工作区变更中完成，禁止批量事后补勾。
3. 每项完成必须按项目规范验证（`bun run test` / `bun run typecheck` / 页面回归）并在根目录 `CHANGELOG.MD` 顶部追加记录（日期、类别、范围、摘要、验证）。
4. 勾选后如发现遗留问题（如测试未覆盖、边界未处理），在该项下方以 `- 遗留：` 追加说明，不取消勾选。
5. 新增发现的问题，追加到对应分类末尾并给出位置与建议；移除或合并某项时注明原因。
6. **逐个修复、逐个确认**：修复完一个问题并验证通过后，先停下向用户汇报，**经用户确认后才能开始修复下一个问题**，禁止连续批量修复多个问题。
