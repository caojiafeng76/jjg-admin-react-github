# 前端交互与反馈规范

> **这是本项目前端页面写法的唯一权威规范。** 新页面按此编写；老页面在分批迁移时向此对齐。
> 视觉 token（颜色、圆角、阴影）的设计来源见 [UI设计调研与改版指南.md](UI设计调研与改版指南.md)；两者冲突时以本文为准。
>
> **样板模块**：`src/features/jintan/*`、`src/features/youmai/*`（以下简称 G2）。不确定怎么写时，照抄 G2 的同类页面。
> `src/features/syney/*` 是最早期写法（G0），**不要**再作为参考。

## 1. 页面骨架

```tsx
<div className="flex h-full flex-col gap-3 overflow-hidden">
  {/* 1. 工具栏：左上角，文字按钮 */}
  <div className="flex flex-wrap items-center gap-2">
    <AddButton handleCreate={handleCreate} permissionKey="feature:xxx.create" />
    <EditButton handleEdit={handleEdit} permissionKey="feature:xxx.edit" />
    <DeleteButton onConfirm={handleDelete} isDeleting={isDeleting} count={n} title="删除工装" itemName="工装" permissionKey="feature:xxx.delete" />
  </div>
  {/* 2. 搜索栏 */}
  <XxxSearch onSearch={setFilters} onReset={resetFilters} />
  {/* 3. 选中摘要（可选） */}
  <SelectedSummaryBar ... />
  {/* 4. 表格 + 分页 */}
  <div ref={tableContainerRef} className="min-h-0 flex-1">
    <TableState loading={isLoading && !data} error={error} onRetry={refetch}>
      <Table ... />
    </TableState>
  </div>
  <div ref={paginationRef}><AppPagination total={data?.total ?? 0} /></div>
</div>
```

| 规则 | 说明 |
|---|---|
| 不加外层 padding | `AppLayout` 的 Content 已有 12px 内边距，页面根节点**不要**再加 `p-4` / `p-6` |
| 不套卡片 | Content 本身就是 `app-card`，页面内**不要**再包 `app-card` / 带阴影的大卡片 |
| 不写页面大标题 | 页面名已在顶栏和标签页显示，页面内**不要**再放 `Typography.Title` |
| 工具栏位置 | 左上角，从左到右：新增 → 编辑 → 删除 → 业务动作 → 导入/导出/打印 |
| 操作入口 | 默认「勾选行 + 工具栏按钮」；行内操作列只在明细子表等确有需要时使用 |

## 2. 反馈

### 2.1 Toast

- **只用** `const { message, modal } = App.useApp()`。禁止 `message.useMessage()` + `contextHolder`，禁止静态 `message.xxx()` / `Modal.confirm()`。
- Mutation hook 用 `useMutationWithInvalidation`（静默，只负责缓存失效），**由调用处**弹提示：

```ts
try {
  await createMutation.mutateAsync(values)
  message.success(feedbackText.created('工装'))
}
catch (error) {
  message.error(getUserErrorMessage(error, feedbackText.failed('创建', '工装')))
}
```

- `useMutationWithMessage` 仅保留给存量代码。它内部已改用 `App.useApp()`，无需再渲染 `contextHolder`。**同一个操作只允许一处弹提示**：hook 里配了 `successMessage`，调用处就不要再弹。

### 2.2 文案（`src/utils/feedbackText.ts`）

句式统一为 **对象 + 动作 + 结果**：

| 场景 | 写法 | 示例 |
|---|---|---|
| 创建 / 更新 / 保存 | `feedbackText.created('工装')` | 工装创建成功 |
| 删除 | `feedbackText.deleted('入库记录', 3)` | 已删除 3 条入库记录 |
| 批量动作 | `feedbackText.batch('审核', '工单', 5)` | 已审核 5 条工单 |
| 导出 / 导入 | `feedbackText.exported('订单', 20)` | 已导出 20 条订单 |
| 失败 | `feedbackText.failed('删除', '工单', reason?)` | 工单删除失败：请稍后重试 |
| 未选择数据 | `message.warning(feedbackText.selectRequired('删除'))` | 请先选择要删除的数据 |

- 前置条件不满足（未选择、状态不允许）一律用 `message.warning`，**不用** `message.error`。
- 标点用全角（，：）；不用感叹号；重试后缀统一写「请稍后重试」。
- 术语统一用「审核 / 反审核」，不用「反审」。

### 2.3 错误原因

- Service 层：`if (error) throw handleApiError(error, '工装创建失败')`。
  - 返回的 `AppError.message` 一定是可直接展示的中文：已识别的错误显示为「工装创建失败：数据已存在，请勿重复提交」；无法识别的英文错误只显示「工装创建失败」。
  - 数据库原文、错误码保存在 `AppError.details` / `code` 中。
- 组件层：toast 用 `getUserErrorMessage(error, fallback)`，**不要**直接 `error.message`。
- 需要看原文时，`TableState` / `FormErrorAlert` / 页面错误态都自带可折叠的「技术详情」（`ErrorTechnicalDetail`），用户可以复制后发给开发。
- 新的常见数据库错误请加到 `errorHandler.ts` 的 `ERROR_CODE_TRANSLATIONS` / `ERROR_MESSAGE_PARTIAL_TRANSLATIONS`。

### 2.4 删除与确认

- 删除**必须**二次确认，统一用 `DeleteButton`（Popconfirm 形态，危险色确认按钮，按钮文字「确认删除」）。
- 调用时**显式传入** `title`、`itemName`、`count`、`permissionKey`，不依赖默认值（默认值是中性的「删除记录」）。
- 其他高风险操作（结案、批量反审核、驳回）用 `modal.confirm({ okButtonProps: { danger: true } })`。
- 手写 Popconfirm 时必须加 `okText="确认删除"` 和 `okButtonProps={{ danger: true }}`。

### 2.5 加载

| 场景 | 写法 |
|---|---|
| 表格首屏 | `TableState loading={isLoading && !data}`（骨架屏），**不要**用 `records.length === 0` 判断 |
| 翻页 / 刷新 | Table 自带的 `loading`（`keepPreviousData` 下不闪骨架） |
| 提交 | Modal 的 `confirmLoading={mutation.isPending}`，表单内按钮用 `loading` |
| 导出 / 打印 | 按钮 `loading`；耗时超过 1 秒的操作配合 `message.loading` |

## 3. 出错与无权限（保留布局）

| 情况 | 用户看到什么 | 实现 |
|---|---|---|
| 列表查询失败 | 表格位置显示「失败原因 + 重试 + 技术详情」 | 查询 hook 加 `throwOnError: false`，页面用 `TableState error={error} onRetry={refetch}` |
| 其他首屏查询失败 / 渲染异常 | **只有当前页面内容区**显示错误 + 重试，菜单和其他标签页不受影响 | `permissionRoute` 自动包裹 `PageErrorBoundary`，无需页面处理 |
| 后台刷新失败（已有缓存） | 继续展示旧数据，不打断 | 全局 `throwOnError` 默认行为 |
| 无页面权限 | 布局内显示 403 页面 +「返回首页」 | `PermissionProtectedRoute` 渲染 `PageForbidden` |
| 账号无档案 / 停用 / 没有任何入口 | `/access-denied` 独立页 | 不变 |
| 地址不存在 | 布局内显示 404 页面 | `router.tsx` 布局内的 `*` 路由 |
| 无按钮权限 | 按钮**禁用 + Tooltip 提示**，不隐藏 | 共享按钮传 `permissionKey`；自定义按钮用 `PermissionButton` |

- 有内联错误区域时，查询 hook **不要**再在 `useEffect` 里弹 toast，否则会出现双重反馈。下拉选项这类没有内联区域的查询，可以 toast 提示。

## 4. 表格

- `size="small"`、`pagination={false}` 配合 `AppPagination`，高度由 `useTableHeight` 计算。
- 空态：`locale={{ emptyText: <TableEmpty title="暂无工装" /> }}`。
- 斑马行必须带暗色变体：

```ts
rowClassName={(_, index) =>
  index % 2 === 0
    ? 'bg-white dark:bg-slate-800'
    : 'bg-slate-50/60 dark:bg-slate-800/60'}
```

- 状态列用 `StatusPill`，不要在模块里各自写 `Tag color` 映射表。
- 每页条数：`DEFAULT_PAGE_SIZE = 10`（`src/config/pagination.ts`）；扫码流水、看板等大列表显式使用 `LARGE_PAGE_SIZE`。

## 5. 搜索与 URL 状态

- 搜索组件：`<Form className="flex flex-1 flex-wrap gap-2">` 配「搜索 / 重置」按钮，回车即搜索（`htmlType="submit"`）。
- 列表状态用 `useUrlListState(['keyword', 'status'] as const)`。
  - 筛选、页码、每页条数**只存在 URL 里**，不要再把 URL 拷进 `useState`。这样刷新页面、从菜单进入、切换标签页时状态都一致。
  - 修改一律 `replace`，不产生浏览器历史；`AppPagination` 也是这样做的。
- 「返回列表」不要用 `navigate(-1)`：从列表跳详情时带上 `state={{ from: listHref }}`，详情页用它返回（参考 `syney/PoDetail`）。
- 点击菜单进入一个已经打开的页面时，会自动恢复该标签页记录的地址。

## 6. 表单与弹层

| 用途 | 容器 |
|---|---|
| 新增 / 编辑 | `Modal`，`destroyOnHidden`，`Form layout="vertical"` |
| 只读详情（字段多） | `Drawer` |
| 确认 | `Popconfirm` / `modal.confirm` |
| 员工端（手机） | 独立路由页面 |

- Modal 宽度只用三档：**520**（≤ 6 个字段，antd 默认）/ **720**（两列表单）/ **960**（含明细子表）。
- 保存失败：在 Modal 内表单顶部显示 `FormErrorAlert`，弹窗不关闭，已填内容保留；toast 只用于删除、导入等非表单操作。
- 校验规则必须写 `message`：`{ required: true, message: '请输入工装编号' }`。

## 7. 格式

| 内容 | 写法 |
|---|---|
| 日期 | `formatDate(v)` → `2026-10-21` |
| 日期时间 | `formatDateTime(v)` → `2026-10-21 14:03`；审计、日志时间用 `formatDateTime(v, { withSeconds: true })` |
| 数字 | `formatNumber(v, digits)`；金额 / 工时保留 2 位 |
| 禁止 | `new Date(v).toLocaleString('zh-CN')`（格式是 `2026/10/21 14:03:22`，和其他页面不一致） |

dayjs 已在 `main.tsx` 全局设为 `zh-cn`。

## 8. 视觉

- 图标：`@heroicons/react/16/solid`，尺寸 `size-4`；不再新增 `@ant-design/icons` 和手写 `<svg>`。
- 颜色：灰阶只用 `slate-*`，且必须成对写 `dark:`。优先使用 token 工具类（`text-primary`、`text-text-secondary`），避免硬编码十六进制颜色。
- 圆角：卡片 / 面板 `rounded-xl`，控件跟随 antd token。不要新增任意值的 `rounded-[..]` / `shadow-[..]`。
- 响应式：管理端按桌面端设计；员工端和扫码页按手机端设计（含暗色）。
